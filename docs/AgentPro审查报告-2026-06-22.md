## 二、部署链路端到端核查

链路：`push → .github/workflows/deploy-backend.yml → SSH → git reset --hard → backend/scripts/deploy-remote.sh（build → alembic upgrade head → up -d → 健康检查）`。

逐链结论：

1. **触发**：`on.push.branches=[feature/agentpro-backend]` + `paths=[backend/**, 工作流自身]`；本轮提交确实改动 `backend/**` → 命中。✅
2. **SSH/鉴权**：`appleboy/ssh-action@v1.2.0`，host/user/key/port 取自 Secrets。逻辑正确，但**需用户先配 5 个 Secret**（见部署文档），本机无 `gh` 无法验证 Secret 是否已配。⚠️ 待用户
3. **服务器拉取**：`git fetch + checkout + reset --hard origin/<branch>`，**不执行 `git clean`** → 保留未跟踪的 `backend/.env`（生产配置不在 Git）。✅
4. **构建/迁移/启动**：脚本用 `BASH_SOURCE` 定位 `backend/`（与 cwd 无关）；`.env` 缺失即中止；迁移在「构建后、启动前」，失败即中止、旧容器继续服务。✅（迁移单头，`upgrade head` 不歧义）
5. **健康检查**：`curl 127.0.0.1:8000/api/v1/health`，与 app 实际路由一致；prod 当前实测 `ok:true`。✅

**无法在本机执行的部分**：真正的 SSH+构建步骤依赖 `gh/docker/SSH` 与用户 Secret，本环境（无 gh/docker、无私钥、且不应直连 prod）无法触发。剩余唯一现场证明 = 用户配好 Secret 后在 Actions 页 `Run workflow` 跑一次，确认脚本末尾输出 `健康检查通过 ✅`。

## 三、发现（按严重度）

### F1 [Medium] 部署无回滚，坏镜像会直接顶替在跑容器
`backend/scripts/deploy-remote.sh` 顺序为 build → migrate → `up -d` → 健康检查。若健康检查在 `up -d` **之后**失败，新（坏）容器已在对外服务，脚本 `exit 1` 不会回滚；且随后的 `docker image prune -f` 可能清掉上一个可回滚镜像（旧镜像在 rebuild 后变 dangling）。
- 影响：一次坏部署会让 prod 处于不可用，直到人工 `git reset` 旧版 + 重建。
- 建议：(a) 给镜像打版本 tag、保留上一个；(b) 健康检查失败时自动回滚到上一个 tag；(c) 至少把 `image prune` 改为保留上一个镜像，或部署后人工 prune。

### F2 [Low-Med] `/agents/{id}/run` 为无状态单轮，且无频控
- 无会话历史/多轮上下文：每次请求只发 `[system, user]`，设计文档提到的「运行记录可留存（会话历史）」尚未实现 → 当前更像「单次执行」而非「对话」。
- 无频控：每次调用都打用户自己配置的模型（耗 token）。虽用的是用户自己的 key，但缺少防误触/防刷。
- 建议：切片 C 后续补「会话历史持久化 + 多轮」；运行端加每用户简单频率限制。证据：`agents/router.py::stream_agent_run`。

### F3 [Low] 纯空白输入可绕过 `min_length=1`
`AgentRunRequest.input` 用 `Field(min_length=1)`，但 `"   "`（空格）能通过校验；端点再 `.strip()` 后变空串发给模型。
- 影响：浪费一次模型调用、返回无意义结果。
- 建议：端点对 `payload.input.strip()` 为空时返回 422，或用 validator 去空白后再校验。证据：`agents/schemas.py`、`agents/router.py::run_agent`。

### F4 [Low] 交付列表/运行校验存在 N+1 查询
`list_delivered_agents` 与 `requirement_is_delivered` 都「先查全部 accepted 评审，再逐条 get spec/job/requirement」。当前规模无碍，用户累计大量已采纳评审时变慢；且每次 run 都重算一遍。
- 建议：用 join 一次取回，或给 run 端点的「已交付」判定加缓存。证据：`agents/router.py`。

### F5 [Low] 系统提示词逐字注入 spec.body（提示注入面）
`build_agent_system_prompt` 把 `objective/capabilities/decisions` 原样拼进 system prompt。当前 spec 是用户自己的，风险低；一旦未来支持「共享/市场 Agent」，他人 spec 即成为提示注入入口。
- 建议：长期对注入内容做分隔/转义，或限定来源为本人。

### F6 [Info] 30s 客户端超时的边界
`apiClient.safeFetch` 默认 30s 超时（流式已豁免）。桌面端目前不调用同步长任务端点，故无影响；若将来前端直连后端同步 `/execute` 类长接口，需单独放宽。
